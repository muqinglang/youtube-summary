# 实现与维护约定

扩展采用 TypeScript 和原生 DOM，不引入前端框架、远程脚本或运行时 CDN。生产构建有六个入口：background、content、page、learn、export 以 IIFE 打包；panel 以 ESM 打包并开启代码分割，让体积远大于面板本身的 PDF 引擎只在真正导出时才加载。

仓库另含一个可选的托管服务端（`server/`），与扩展**共用同一份** AI 流水线源码，见 [服务端说明](../server/README.md)。

| 层                 | 文件                                                                 | 职责                                                                                   |
| ------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |

| 隔离内容脚本       | `src/content/index.ts`、`protocol.ts`、`surface.ts`                  | 校验桥接消息、挂载点赞旁的独立学习页入口                                               |

## 数据如何流动

1. 页面桥在 `document_start` 安装被动字幕观察器。读取时优先使用当前视频已收到的原生字幕，之后请求原始签名地址；若没有有效正文，使用正常的「显示转录内容」按钮读取原生面板。不会补造签名或修改字幕 URL 参数。
2. 点击入口后，后台绑定源视频并打开 `learn.html`。学习页通过源标签读取元数据、字幕，使用 YouTube 嵌入播放器独立播放。右侧 `panel.html` 通过同源父页面读取学习状态。网页消息不能调用设置、AI 或导出接口。
3. 翻译引擎默认是「默认字幕」= Google 公共网页翻译接口（`translate.googleapis.com`），只有用户显式选择「AI 字幕」才改用模型。译文保持原字幕 ID 与时间轴。
   字幕载入后由面板驱动**随播放渐进翻译**（Trancy 式）：Google 引擎一次流式翻译整片；AI 引擎以约 24 句为批、只翻译播放位置前方 ~60 句的窗口以节省额度，播放头推进时按最小批量续翻，「翻译全部」按钮才会顺序翻译整片。渐进过程用独立控制器而非主任务通道，不占用总结 / 问答按钮；后台仍逐批校验字幕 ID 一一对应。整份译文按 视频+语言+引擎+模型 哈希写入学习缓存并去抖持久化，重开视频或切换语言时优先回填缓存、仅补翻缺口。切换视频、语言、引擎或关闭自动翻译立即取消并清理。
4. AI 任务由面板将字幕、用户要求和任务类型交给后台；后台独立检查数据结构、数量和时间范围。
5. 后台把字幕分批发送给配置的 AI 服务，验证输出 JSON、字幕 ID、时间引用和导图节点范围。
6. 面板展示通过验证的结果，Google 与 AI 使用独立缓存键，避免不同引擎译文混用；导出直接使用本地结构化结果。

## 关键实现约束

- **模型目录**：`src/shared/providers.ts` 是服务商、地址、模型与能力的唯一配置源。界面只允许选择目录项；后台再次校验固定端点和模型。OpenAI / DeepSeek 使用 Chat Completions，Claude 使用 Messages、独立鉴权头和文本块解析。未知旧配置保留为内部 legacy 模式，界面不新增自由填写地址入口。
- **内容目录（章节）**：右侧「章节」标签按优先级取三种来源：AI 内容目录（`outline.sections`）> AI 总结章节（`summary.sections`）> **视频自带章节**（`content/chapters.ts`）。都没有时才显示生成入口，所以打开即可用。标题栏标明当前来源，原生用「章」、AI 用「节」；显示原生章节时在标题栏保留一键生成 AI 目录的入口，避免空状态被占掉后无法升级。来源种类参与渲染身份，AI 目录替换掉内容相同的原生章节时也会重新标注。
- **引导提问**：在看之前由模型依据字幕提出 5~8 个问题，按视频回答的先后排序，时间戳走与目录、总结相同的吸附逻辑。答案默认收起，展开与跳转是两个并列按钮而非嵌套，让「先去找答案」保持默认路径。
- **字幕显示**：视频下方只有一个字幕带，原文/译文依显示模式渲染；显隐偏好独立于当前句。播放器公布模块能力后关闭原生 CC，模块迟加载可再执行一次，避免每条字幕触发切换或陷入事件循环。手动打开的原生 CC 不会被持续抢回。

- **密钥边界**：后台返回公开设置时剔除密钥。存储限定为可信扩展上下文；页面桥及隔离脚本不持有密钥。已记住的凭据绑定服务来源域，更换域名不会复用旧服务密钥。设置读写串行处理。
- **长文本处理**：每批同时约束字幕数量、文本和序列化大小。总结采用分段摘要和递归归并，所有字幕都进入处理链，不用「截取前几千字」冒充全片总结。压缩摘要仍可能损失细节，需用引用回看。
- **AI 调用健壮性**：分段分析单次 45 秒超时、全片汇总 90 秒。限流与超时按各自预算重试；模型返回结构不符时把出错的字段路径回喂给它再试。输出校验刻意宽松——超长文本截断、坏元素丢弃、`"4:19"` 这类时钟格式转秒——只有完全无法使用的结果才失败。个别片段始终失败会被跳过并在结果上标注覆盖率，不再丢弃整轮工作。
- **输出可信度**：字幕和模型文本均视为数据。提示词明确区分用户要求和字幕内的指令；界面转义文本，打印页不执行来源脚本。所有 AI 引用时间须存在于输入字幕证据中。
- **生命周期**：每个面板任务通过独立 runtime Port 传输结果；任务运行时发送心跳，关闭学习页、页面卸载和手动取消都会中止请求。源 YouTube 页面导航不会替换正在学习的视频。单请求有限超时与重试，任务最长 30 分钟，同时最多两个后台 AI 任务。
- **入口挂载**：源 YouTube 页面只挂载点赞旁按钮，不改变页面宽度。轮询恢复被 YouTube 替换的操作栏，并保留唯一入口。学习页按视频 ID 复用，最多索引十个会话；淘汰会话时清理对应字幕。
- **播放器隔离**：只接收嵌入 frame 的 YouTube 来源消息，并检查消息中的视频 ID。播放器内切换到其他视频时暂停同步、清除旧双语显示，提示重新打开学习页。字幕跳转、倍速、播放控制作用于学习页播放器，不操作源页面时钟。DNR 仅为本扩展发起的 YouTube embed 子框架请求设置带有真实扩展 ID 的客户端 Referer，遵循 [YouTube 嵌入播放器身份要求](https://developers.google.com/youtube/terms/required-minimum-functionality#embedded-youtube-player)。
- **异步隔离**：视频切换或字幕导入递增版本。缓存读取、网络结果及缓存写入之后均检查任务状态与版本，防止旧结果覆盖新视频。
- **字幕性能**：保留完整数据，但 DOM 每次渲染最多 100 条字幕；播放通过二分定位当前句，只更新必要状态，窗口外自动跟随时才重绘。
- **缓存边界**：AI 学习缓存最多 20 条、约 4 MB，30 天过期。只读取 `learning:` 前缀的键，不枚举读取私有密钥值。缓存键不包含播放时间、暂停状态等动态信息。当前学习页的字幕另存于会话存储，单份序列化内容小于 150 万字符时保存，浏览器会话结束清除。
- **构建边界**：只复制 `extension` 和打包 `src`；不打包测试、开发者配置、原型截图或 `node_modules`。构建脚本仅替换验证后的项目 `dist` 路径。

## 已定的方向

**播放器保持 iframe 嵌入，暂不注入 YouTube 原页。**

两种做法的实质差别只有一条：`youtube.com/embed` 是跨域 iframe，拿不到画面像素，因此做不了关键帧抽取、幻灯片 OCR 和截图剪藏；注入原页可以，代价是把整个两栏工作台搬进别人的 DOM，持续承受改版、Trusted Types 和布局摩擦——挂一个入口按钮就已经需要轮询恢复被替换的操作栏，可见这份摩擦是常态。

既然近期不做画面理解，逼迫做这个选择的因素就不存在了，iframe 的其余短板（字幕只能在画面下方、全屏时字幕层在 iframe 外）对「内容学习」定位不致命。因此维持现状，不为一个尚未启动的能力提前重写。

真要做画面理解时，**首选混合方案而非搬家**：`sendToYoutube` 已有向源标签页发命令的通道，加一条抽帧命令即可——让源标签页把暂停中的 `<video>` seek 到目标时间再 `drawImage`。动手前必须先验证 YouTube 的 MSE `<video>` 能否 drawImage 而不污染 canvas；现有 e2e 用的是普通 `<video>` 夹具，证明不了这一路。

托管服务端已作为独立边界实现（见 `server/`），运营方密钥只存在于服务端进程，不进扩展包。界面变化和算法变化分别验证，不为简单样式调整增加重复测试。

后续优先级：真实 YouTube 字幕获取的跨会话验证 > 内容学习功能（术语表、划词解释、剪藏笔记）> 跨视频知识库 > 无字幕视频转写与画面理解。
